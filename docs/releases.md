# Releasing gradletest-axi

Releases are generated by GoReleaser and published by GitHub Actions. A release
contains static macOS, Linux, and Windows binaries for amd64 and arm64,
platform archives, and a SHA-256 checksum manifest.

## Agent-assisted release

Use the repository's
[`release-gradletest-axi`](../.agents/skills/release-gradletest-axi/SKILL.md)
Agent Skill to prepare and publish a release. It curates `CHANGELOG.md`, runs
local validation, waits for CI on the exact release commit, creates the
annotated tag, waits for GoReleaser, publishes the curated release notes, and
verifies the resulting assets and installation.

The manual steps below are a fallback and a description of the automation.

## Versioning

Use semantic versions prefixed with `v`. Version `v1.0.0` declares the CLI
contract stable. Increment:

- The patch version for backward-compatible fixes.
- The minor version for backward-compatible functionality.
- The major version for incompatible changes.

## Publish

Start from a clean `main` branch that is synchronized with `origin/main` and
has passing CI. Move the curated `Unreleased` entries in `CHANGELOG.md` into a
dated version section, update its comparison links, run the local checks, and
commit and push that change. Wait for CI to pass on that exact commit.

Create and push an annotated tag:

```sh
git tag -a v1.0.0 -m "gradletest-axi v1.0.0"
git push origin v1.0.0
```

The `release` workflow validates the project, builds all configured targets,
creates the GitHub Release, and uploads the archives and `checksums.txt`. It
uses the repository-provided `GITHUB_TOKEN`; no additional release secret is
required.

After GoReleaser succeeds, replace its generated commit notes with the matching
curated version body from `CHANGELOG.md`.

## Verify

After the workflow completes:

1. Confirm the release is published rather than draft and contains six
   platform archives plus `checksums.txt`.
2. Download all archives and the checksum manifest, then verify every SHA-256
   digest.
3. Confirm an archive contains `README.md`, `CHANGELOG.md`, and
   `docs/axi-principles.md`.
4. Extract the binary and run `gradletest-axi --version`; it must report the
   pushed tag.
5. Install from source with
   `go install github.com/mrobertsatpolitico/gradletest-axi/cmd/gradletest-axi@v1.0.0`
   and verify that binary reports the same tag.

Do not move or replace a published tag. Publish a new patch version for a
release correction.
